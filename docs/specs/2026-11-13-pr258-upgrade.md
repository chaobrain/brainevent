# Review fixes for the data-format reorganization (PR #258)

## Goal

Make PR #258 (subpackage layout, `CSRConfig`, hybrid CUDA CSR/SDDMM kernels,
TCSR as a CSR subclass, prepared delay delivery) correct on GPU, as fast as the
code it replaces, and non-breaking where the old design was not worse.

## Decisions

- **No `backward_algorithm`.** The event type alone decides the weight
  gradient: binary events (`BinaryArray`, bool, `weighted=False`) use the
  activity mask, `WeightedArray` / `weighted=True` use event values. Both are
  the exact derivative of their forward, so forward- and reverse-mode agree.
  A surrogate rule (the former `pp_prop`/`weighted_float`) silently gave
  `jax.grad` results that disagree with the forward; nothing downstream used it.
  `TCSR(backward_algorithm=...)` fails with a migration message.
- **Breaks only where the new design is better.** `HybridConfig`,
  `get_hybrid_config` and the non-layout `csr_delay_deliver(_p)` /
  `CSR.delay_deliver` are replaced by strictly better APIs and raise migration
  errors through `brainevent._deprecation`.
- **Functional delay layout.** The PR's stateful `delaycsr` (mutable ring and
  head, `x @ W` mutating `W`, per-step O(nnz) validation, dense CPU path, rings
  allocated per object) measured 16x slower than main on GPU and broke
  brainspike's `CSRDelayLayout` usage. Keep the stateless `CSRDelayLayout` +
  `csr_delay_deliver_layout` API, validated once at build, with the faster of
  the hybrid and delay-major CUDA kernels and main's event-driven Numba CPU
  kernel. Time and state stay with the caller (brainstate/brainspike).
- **Shared CUDA traits.** One `include/brainevent/{cuda_traits,op_traits}.cuh`
  replaces four identical copies; built-in `.cuh` headers enter the kernel
  cache key and the wheel.
- **Half precision accumulates in float32** in the hybrid kernels; the
  FP16/BF16 cuSPARSE comparisons are re-enabled instead of disabled.
- **No recompilation per redrawn matrix.** Static plan statistics are bucketed
  so same-shape matrices share executables, as the 0.4.0 dynamic-leaf design
  requires.

## Step plan

1. Remove `backward_algorithm`; consolidate CUDA traits; add migration errors.
2. In parallel, with disjoint files: CSR hybrid fixes (plan-free fallback for
   transposed MM, f32 accumulation, no nvcc at construction, bucketed plans,
   sm_70 guards, overflow safety, config store robustness); TCSR (sm_70 guards,
   lazy/deduplicated tile geometry, backend checks before mirrors, exposed sort
   permutation); SDDMM and FFI gate (cast-consistent activity, branch-free
   non-finite handling, cuSPARSE handle/workspace/library selection, gated CUDA
   callbacks, bounded shutdown wait); the functional delay layout.
3. Documentation, changelog and repository hygiene.

## Verification

- Full CPU suite (including `slow`) and `JAX_ENABLE_X64=1` for dtype paths;
  GPU suites for `_csr`, `_tcsr`, `_sddmm`, `_fcn`, `_op`, delay, including
  FP16/BF16 cuSPARSE comparisons; `nvcc -arch=sm_70` compile checks; mypy.
- A wheel contains every runtime CUDA source and header and runs from outside
  the checkout.
- Delay delivery per step is at least as fast as main (GPU and CPU); a jitted
  function is compiled once across redrawn same-shape matrices.
- brainspike's delay tests pass unchanged against this branch.
