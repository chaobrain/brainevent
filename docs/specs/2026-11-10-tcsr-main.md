# TCSR main integration

## Goal

Implement `_tcsr/README.md`: `TCSR(CSR)` owns only sorted construction,
explicit binary-MM tile preparation and dispatch, and the extra pytree payload.
Canonical storage, numerical operations and gradients remain in CSR/operator code.

## Decisions

- Store immutable plans in `StructureCache.tile_plans`, keyed by direction,
  batch and value dtype. Copy cache containers when preparing or replacing a
  mirror, sharing unchanged arrays. Structural changes discard tile plans.
- Keep preprocessing outside JIT. Trusted assembly and pytree restoration never
  inspect leaf contents. Preserve duplicates and homogeneous storage.
- Select the tiled operation with `lax.platform_dependent` for the actual CUDA
  compilation target and the public CSR backend resolver. Use CSR for other
  supported choices or missing plans. Native resource failures remain explicit.
- Keep the documented CSC transpose boundary and the existing binary primitive's
  canonical operands, units and differentiation rules.

## Steps

1. Extend shared cache lifecycle and implement typed preprocessing plans.
2. Add the CSR subclass, factories, preparation and pytree extension.
3. Connect platform dispatch and switch the package export.
4. Verify CPU fallback, CUDA execution, lifecycle and JAX transformations.

## Verification

Tests live under each area's `test/` directory with the `foo_test.py` suffix.
Cover stable sorting, empty structures/batches, multi-key cache isolation,
mirror invalidation, type preservation, units, placeholder/float0 pytree leaves,
JIT/scan/vmap and direct/mirror gradients. Run focused existing regressions,
new-code mypy checks, and Python coverage. Report GPU and native-memory checks
separately when the required tools are available.
