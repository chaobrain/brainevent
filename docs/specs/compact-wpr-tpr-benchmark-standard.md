# Compact WPR TPR 测试标准规格

## 范围与交付

为 `brainevent/_tcsr/dev/new_mv_operator/dev/stage_compact_stage_wpr` 的后续重写制定测试标准：第一阶段完全压缩活动行，第二阶段分别采用完全 WPR 或完全 TPR。标准正文位于用户指定的 [benchmark/测试标准/README.md](../../brainevent/_tcsr/dev/new_mv_operator/benchmark/测试标准/README.md)。

本次仅新增文档，在当前 `mm-optimizing` 工作分支完成，不修改算子、Gini 生成器或测试代码，不执行全量 GPU benchmark。后续代码实现须先描述方案并获得批准。

## 固定需求

- 方阵边长为 `10k、100k、1000k、2000k`；用户已确认全部按 `k=1000` 解释。
- 结构密度为 `1e-4、1e-3、1e-2`，分别对应万分之一、千分之一、百分之一。
- 全部 CSR 行长的目标 Gini 为 `0、0.4`。
- 三个维度取完整笛卡尔积，共 `4 × 3 × 2 = 24` 个结构组合；每个结构遍历事件活动率 `1e-4、1e-3`，每个变体共 48 条记录。seed 固定为 0。
- 使用已有 `gini_row_lengths.py` 的 Gini 定义、正 Gini 生成方法、行长约束及 `0.002` 容差。Gini 为零时使用等长行，并用同一计算函数复核。

## 关键约束

密度与非零元数量必须精确，不得为了生成某个 Gini 而修改密度、允许重复列或放宽误差。生成器返回的实际 Gini 必须保存；不可实现和资源不足的组合仍须保留在完整清单中。

现有生成器禁止空行。当平均行长为 1 时，只能得到 Gini 为零的分布，因此 `N=10k、d=1e-4、Gini=0.4` 这一结构需预先标明分布限制，在两个活动率下共 2 条记录；其余 23 个结构仍须经过实际生成校验和资源预检。

测试标准需明确阶段职责、完整输出正确性、活动率与矩阵密度的区别、可复现输入、计时范围、64 位偏移需求、内存预算和跳过原因。不能用第二阶段的独立耗时替代完整算子耗时，也不能把资源跳过计作正确性通过。

## 文档验收

1. 正文列出 12 个尺寸与密度组合，每行给出两个 Gini 用例编号，恰好覆盖 24 项。
2. 每行的平均行长、精确 `nnz` 和 CSR 偏移类型可以由整数运算复核。
3. 区分数学不可实现、当前生成器约束不可实现、资源不足、类型不支持、生成失败和计算失败。
4. 包含阶段边界、空输入、尾部行、队列容量、跨调用复用、索引溢出和数值验证要求。
5. 后续 Python 实现使用同目录 `foo_test.py`，有效覆盖率须大于 90%，mypy 无错误，兼容 JAX >= 0.8.0；这些是后续实现门槛，不作为本次纯文档变更的测试结果。
